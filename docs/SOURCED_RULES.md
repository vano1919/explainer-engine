# Sourced production rules (BP-)

**Decision D-59 (the creator, 2026-10-19): no production rule is law by itself.** Every number a validator enforces lives in
one registry, `explainer_engine/standards/sourced_rules.json`, with the sources that back it. The table below is generated
from that file (`python -m explainer_engine.standards.sourced_rules write`); edit the JSON, never the table.
`tests/unit/test_sourced_rules.py` fails when the table and the registry differ, when a rule lacks its sources, or when
`enforced_by` names code that does not exist. Code reads a threshold with `sourced_rules.T("BP-06", "max_words")` and
never copies the number; the other documents link a BP id instead of restating it (D-23 extended to numbers).

## How a rule is graded

| status | meaning |
|---|---|
| **binding** | at least two of the three source types back it (A an article, official page or study; B a book; C a YouTube video or vlog); enforced in code; may FAIL |
| **hypothesis** | one source type only; checked as REVIEW, never FAIL; the number is the one the project already used (the research confirmed or could not settle it) |
| **house** | the creator's own dated decision; kept here so code and documents agree on it |

The research files behind the rules (fetched 2026-10-19, every URL opened, nothing cited from a snippet): narration pace, hooks,
writing for the ear, humour and ElevenLabs (40 sources); audio loudness, balance, ducking, sync, density and music (63);
camera moves, accents, text, continuity, expression composites (51); retention cadence, structure and Shorts (55). They are in
the project's shared folder under `SYSTEM_AUDIT_2026-10-19/` with the contradiction audit that started this
([research/SYSTEM_AUDIT_2026-10-19.md](research/SYSTEM_AUDIT_2026-10-19.md) is the repository copy).

What the research did **not** find, so the project's numbers stay hypotheses: a measured pace of the big explainer channels; any
study of sentence or paragraph pause lengths; a rhetorical-question rate; joke density for explainers; a sound-effects-per-minute
band; a parallax amplitude; a cut-type ratio ("90 % hard cuts" is a house convention); organic (non-ad) Shorts safe margins;
a YouTube loudness target (YouTube publishes codecs only; -14 LUFS is inferred from measurements).

## Where the rules bite

- **Narration** (BP-01..15): one pace band (BP-01), the hook in one of four forms (BP-03), the 30-second contract (BP-04),
  sentences for the ear (BP-06..08), humour (BP-09, BP-10), no press-release lines (BP-15); `scripting/narration_lint.py`
  N-01..N-14, `qa/engagement.py`, `qa/scorecard.py`.
- **Shorts** (BP-11..13, 29, 44..48): the spoken hook inside the first second, word budgets per band, open premise, captions,
  safe zone, posting spread and re-edit triggers; `production/validate.py` PV-28/PV-34, `production/shorts.py`.
- **Motion, text and faces** (BP-20..35): scale and pan limits, easing, shake only on impact, flash safety, text holds and
  safe areas, continuity, dissolves on period boundaries only, expression lead and hold, anti-sticker composites;
  `edit/motion_lint.py`, `edit/shot_rules.py`, `production/continuity.py`, `production/accents.py`, `production/faces.py`.
- **Rhythm and structure** (BP-40..43): section-aware stills, the 25-35 s pattern interrupt, microhooks, abrupt endings;
  `edit/board.py`, `qa/engagement.py`.
- **Audio** (BP-50..63): loudness and true peak gates on the delivered file, dialogue as the anchor, LU-based background
  floors, ducking numbers, asymmetric sync, purpose and density of effects, no repeated sample, one-shots vs loops, narration
  consistency, room-tone pauses, the Shorts profile, spotted music, stereo 384 kbps delivery; `qa/targets.py`,
  `audio/layers.py`, `audio/duck.py`, `audio/seams.py`, `audio/pause_pad.py`, `audio/sfx_library.py`,
  `production/assemble.py`, `production/shorts.py`.
