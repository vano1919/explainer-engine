# Gemini consistency rules (GC-): people and places that stay the same across an episode

Since v4.3 (2026-11-12) the episode's pictures are made by the creator in the **Gemini chat's built-in image tool**, inside his
subscription, free, 6-12 pictures per chat turn at the tool's native 16:9 size (1376x768). The engine cannot call that tool: it
**exports turn packs** (prompt, references to attach in order, target file name) and **takes in** the files he drops back, then gates
them (`explainer_engine/imagegen/turn_pack.py`, CLI `python -m explainer_engine.imagegen.turn_pack`). The paid Gemini API client
(`imagegen/gemini.py`) stays in the repo as an optional route, **off by default**: a real call needs the switch
`EXPLAINER_GEMINI_API=on` (set only for a batch the creator approved with its price) and a model whose entry in
`config/model_lifecycle.json` has a vendor source and a `checked` date at most 30 days old (`core/model_lifecycle_guard.py`,
plan P3.8; the archive's model names carry `checked: null` and allow no paid call).

Sources of these rules: the creator's message of 2026-11-12 09:38 UTC (Gemini's own account of how the 28 Toba pictures were made:
anchors from text only, then per-shot anchors), the v4.3 generator he sent (two-stage reference chain), the v4.3 archive's
`GEMINI.md` (reference library, turnarounds) and our own rules of 2026-11-07 ([SCENE_REUSE_RULES](SCENE_REUSE_RULES.md) HI-01..05
cast registry and faces, LV-01..05 one place one look, RF-04 reference order). Where a rule there and here say the same thing, the
older id stays the canonical one and this page cites it; the GC ids below are the Gemini-chat specifics.

| ID | Rule | Checked by | Severity |
|---|---|---|---|
| GC-01 | **Anchors first, from text only.** An episode's character and place anchors are made before any scene picture, with NO picture attached: an attached outside style sample leaks its people into the episode (the boy, the bearded man and the dog of the 2026-11-11 sample). No outside style sample is ever attached, in any turn. | `turn_pack.export` refuses an anchor item with references and any item whose reference is not an episode anchor or the shot's own start frame | FAIL |
| GC-02 | **A shot attaches only the anchors of the people and the place in it**, in a fixed order: people in the order of `character_ids`, then the place (`location_id`), then props; at most the tool's reference limit (`MAX_REFERENCES`). A missing anchor file stops the pack (no silent drop). | `turn_pack.export` | FAIL |
| GC-03 | **One style sentence opens every prompt** (the episode look's `style_sentence`); anchor prompts and scene prompts differ only by the scene clause "keep the exact faces, costumes and designs of the attached reference images" (`KEEP_CLAUSE`). | `turn_pack.export` builds both; `check_prompt` | FAIL |
| GC-04 | **Each hero is written with the same words in every prompt**: the verbatim registry text (age, build, skin, hair, face, garment, prop; HI-01, HI-02, HI-05). | `check_prompt`: the hero's registry text is a substring of every prompt that names the hero | FAIL |
| GC-05 | **One place, one look**: a place keeps its anchor; a new angle of the same place is asked for as that place, by name, with its anchor attached (LV-01..LV-05 decide when a second drawing is allowed). | `turn_pack.export` (place anchor attached) | FAIL |
| GC-06 | **One moment per picture, in plain scene language**: who does what, where, in which light; no tag lists, no camera jargon chains, no second action. | `check_prompt` (REVIEW on a list of more than `MAX_COMMAS` commas or two "then"/"while" actions) | REVIEW |
| GC-07 | **Letter-free pictures**: no text, signs, labels or plaques in the prompt or the picture; numbers and names are drawn by Python (maps, cards). | `check_prompt` (words that ask for text) + intake's lettering heuristic (REVIEW) | FAIL / REVIEW |
| GC-08 | **A turn carries one scene or one place**: the tool sees neighbours of the same look; a pack never mixes two episodes, and mixes places only when a scene moves between them. | `turn_pack.plan_turns` | FAIL |
| GC-09 | **An end frame is asked for with its own start frame attached** (first), then the anchors, so the pose changes and the world does not. | `turn_pack.export` orders end items after their start item, in the next turn | FAIL |
| GC-10 | **One episode, one chat**: everything of an episode is made in one Gemini chat with that episode's anchors only (the Waterloo leak happened across sessions); the pack's instruction block says so and names the episode. | the instruction block; intake refuses files of another episode's pack id | FAIL |
| GC-11 | **Faces read as live-action actors in a warm adventure film, never as 3D-animation characters** (the creator, 2026-11-12: the environment look is approved, the faces are rejected as "too round, a cheap modern cartoon"; 10:12-10:15 UTC: the target is a live-action adventure film's charm, like the *Astérix* films and the new *Jumanji*, with a handwriting of our own, not a generic look). The face part of the style sentence is the look's `face_sentence`, set in the reference round with him; the 3D-cartoon face words of the v4.3 preset ("expressive eyes", "smooth sculpted", "cute", "3D animation", "Pixar") are refused. | `check_prompt` | FAIL |
| GC-12 | **Intake gates every file before it enters production**: it decodes, 16:9 within 1 %, its native size is what the route gives (the episode's `image_native_min_long_side`, 1376x768 for the chat tool) or more, no letterbox bars, no visible watermark band, not a duplicate of another file, named for a queue item of this pack. A failing file is listed in the next turn pack; it never enters G7. | `turn_pack.intake` | FAIL |
| GC-13 | **Identity is checked, not trusted**: every picture with a named hero is compared with that hero's anchor (face embedding when the free face tools are installed, otherwise a contact sheet for the creator); a miss goes back into the next pack once, then to the creator. | `turn_pack.intake` (identity hook) + contact sheet | REVIEW |
| GC-14 | **Resolution route (the creator, 2026-11-12 10:04 UTC, plan 0.7):** every picture comes free from the chat tool at its native size and gets a free local 2x upscale to the working master (2752x1536); a sharpness/face-detail gate runs on the finished 1080p frame; only close-up and medium-close-up hero shots that fail it are re-made at 2K by `gemini-nano-banana-2.1` on the batch tier with the chat picture attached ("same picture at 2K"). That re-make is PAID: each batch is a remake list with its price, asked first, through the ledger and a cap; no other picture is ever paid for. | `turn_pack.promote` (a chat picture is a `draft` until its upscaled master is 16:9 with a long side of at least the episode's `image_min_long_side`; without an installed upscaler NOT_RUN, never a plain resize); `turn_pack.remake_list` (lists only CU/MCU hero shots with a FAIL sharpness row, priced; NOT_RUN when no frame was measured) | FAIL |
| GC-15 | **The automated chat route is a session on the creator's PC** (Claude in Chrome driving his Gemini chat: paste pack, wait, download, drop into the episode folder), then the same intake gates; manual pasting stays the fallback; the PC session never starts a paid run. | the pack's instruction block; intake is the same for both routes | written rule |
| GC-16 | **Pictures are made with the chat's Flash image model, never Argon (Gemini Pro)** (the creator, 2026-11-12 10:15 UTC: Flash makes the same picture and the chat limit is not used up). | the pack's instruction block names the model; intake records the model the creator states | written rule |
| GC-17 | **One prompt, one picture; no instruction-only turn** (reference round 1, 2026-11-12 10:15 UTC: the chat's image mode at 16:9 draws ONE picture per prompt, about 20 s each, and a standalone instruction turn is drawn as a picture). A pack is a list of self-contained prompts sent one after another in the same chat; anything the tool must know is inside each prompt. | `turn_pack.instruction_block` (operator notes are outside the prompt blocks; every prompt carries the style sentence) | written rule |
