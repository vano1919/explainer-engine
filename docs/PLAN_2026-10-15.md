## Context

The creator wants a solo-operated, faceless YouTube channel of **original 2D cartoon/vector explainers** (long-form + standalone
Shorts) and a semi-automated, resumable, QA-gated production pipeline that runs on an i5-8400 / RX 5700 8 GB / 16 GB RAM Windows
PC within hard budgets (Gemini ≤ US$10, vidIQ ≤ 200 credits, no subscriptions without need, never auto-publish). A research
report and a channel matrix already exist; the job is to grade them, make the strategy and architecture decisions, audit the
existing TMR repo for reuse, and define a 60–90 s prototype gate before any long-form pipeline. This file is the Section-24
package (A–H). After approval it is split into the canonical `docs/` set listed in G, **in a new separate repository**
(creator decision D-21); the TMR repo and its branch `claude/master-directive-prompt-5rmv2y` receive no changes. Creator
decisions taken during planning: D-13 (Claude Code sessions draft research and scripts) and D-21 (new repo).

## C — Creative specification (canonical home after approval: `CREATIVE_STYLE_BIBLE.md`, `NARRATION_AND_LANGUAGE_GUIDE.md`, `TITLE_THUMBNAIL_SYSTEM.md`)

**Tone:** a knowledgeable friend showing you something neat. Curious, warm, a bit dry. Humour is situational and visual (Kit's
reactions, literal visual metaphors); ≤ 1 verbal joke per ~60 s; never at people's expense; never a fake fact for a laugh.

**Mascot "Kit" (original):** box body (w:h 1 : 1.15, corner radius 12 % of width), two lid flaps (rig parts; opening the lid =
the reveal action), front face: two oval eyes with pupils, eyebrows (the main expression driver), mouth with 6 viseme shapes
(reuse the phoneme→opening grouping idea from `tmr_engine/render/visemes.py`), stick limbs 10 px, mitten hands. Kit narrates:
lip-sync when on screen, voice-over otherwise. 8 expressions (neutral, curious, surprised, smug, confused, delighted, worried,
deadpan) and 10 poses (stand, point L/R, shrug, lean-in, hold-prop, lid-open, peek-out, facepalm, wave-off). Canonical reference
sheet SVG `assets/characters/kit/kit_reference.svg`; every pose is composed from the same parts, never redrawn.

**Colour tokens** (semantic, contrast-checked in Phase 2):

| Token | Hex | Use |
|---|---|---|
| `ink` | #1F2430 | outlines, body text |
| `paper` | #FFF8EC | default background |
| `kit_card` / `kit_shadow` | #E0A458 / #B97A35 | mascot body / shade |
| `answer_coral` | #FF6B5B | *the* answer/key object (one per shot) |
| `mechanism_teal` | #2EC4B6 | arrows, flows, labels of the mechanism |
| `support_blue` | #4D9DE0 | secondary objects |
| `true_green` / `false_red` | #7BC950 / #E5484D | myth checks — always with ✓/✗ icon, never colour alone |
| `uncertain_amber` | #FFC145 | "evidence is mixed" badge |
| `night` | #2B2D42 | dark scenes, Short end cards |
| `grey_mid` | #8D99AE | inactive/background props |

**Shape grammar:** rounded rectangles = human-made things; circles/blobs = natural things; sharp triangles only for danger.
Stroke 6 px (characters) / 4 px (props) at 1080p, round caps/joins; flat fills + one shade; no gradients except a background
vignette. **Type:** Fredoka (display/titles), Inter (labels/captions; already used by the repo). Both OFL — licence recorded.

**Narration & language:** contractions, active voice, direct address ("you"), concrete analogies, ≤ 1 rhetorical question per
section, jargon defined on first use, sentences mostly 8–18 words with variety. Flag-for-review list (never auto-delete):
"Have you ever wondered", "imagine", "here's the thing", "but here's the twist", "in today's video", "let's dive in",
"mind-blowing", "insane", "you won't believe", "game-changer", repeated sentence openings, > 2 rhetorical questions/section,
unsupported superlatives, closing summaries that restate everything, CTA begging. Detector reuses the negation-aware lexicon
approach of `tmr_engine/audit/lexicons.py`.

**Hook framework (per format):** first frame shows the object + Kit already doing something; first sentence states the
puzzle as a concrete observation, not a greeting; subject and relevance clear within ~10 s long-form / ~3 s Shorts [HYP]; the
promise is answered (at least in short form) before 40 % of runtime, then deepened; no false stakes. Each hook spec records:
first frame, first visible action, first sentence, on-screen text, sound event, perceived question, time-to-clarity,
transition, failure risk, where the promise is paid.

**Titles/thumbnails:** mechanism library (consequence, hidden reason, misconception, unexpected outcome, comparison,
documented turning point) with exaggeration-risk notes; no copied titles. Thumbnail: 1280×720 PNG, ≤ 1 focal object + Kit,
≤ 4 words, `answer_coral` on the key object, 10 % safe margin, test at 168×94 px downscale; rendered by Remotion `renderStill`
from the episode's own assets (editable source = the composition + props JSON). Pre-publication score = checklist only; no
"CTR prediction".

### E.2 Boundaries and data flow

```
episode.yaml ─► S01 intake ─► S02 suitability ─► S03 research dossier ─► S04 claim map ─► S05 script ─► S06 editorial QA
   ── CREATOR APPROVAL #1 (script + claims) ──►
S07 storyboard (schema v1) ─► S08 assets (reuse search, new SVG, manifest) ─► S09 narration (Kokoro) + word/phoneme timings
   ─► S10 timing reflow (storyboard times ← real audio) ─► S11 scene renders (Remotion, per-scene, cached) ─► S12 audio mix
   ─► S13 assembly (concat + mux) ─► S14 Shorts (vertical storyboards, own TTS/mix/render) ─► S15 thumbnail + metadata
   ─► S16 technical QA + editorial QA + review bundle ── CREATOR APPROVAL #2 (publish) ──► S17 manual upload + analytics record
```

- **Python orchestrates everything** (package `explainer_engine/` in the new repo); **Node renders pictures only**
  (`render/`, a Remotion project in the same repo). Remotion renders **muted** video; all audio is mixed in Python (loudness control,
  reuse of tested code).
- **Contracts:** JSON Schema files in `explainer_engine/schemas/` are canonical (`episode`, `dossier`, `script`,
  `storyboard`, `asset_manifest`, `audio_events`, `timing`, `job_state`, `final_manifest`, all `version: 1`). Python validates
  with `jsonschema` (already in `requirements.txt`, currently unused — no new dependency; schema validation is a known repo gap). TS types generated from the same schema (`json-schema-to-typescript`, dev-only); Remotion
  re-checks referential integrity at load and throws.
- **Finite animation vocabulary (v1):** `Move, Scale, Rotate, Fade, Reveal(wipe|pop|draw), Draw(path), Bounce, Shake,
  FollowPath, ChangeExpression, ChangePose, LipSync, LidOpen, SwapProp, PanCamera, ZoomCamera, Highlight, Count(number),
  Label`. The schema enum is the vocabulary; an unknown action is a validation FAIL, never a silent no-op.
- **Timing:** storyboard times are written relative to narration anchors (`at: {word: "w_0123", offset_ms: -200}`); S10 turns
  anchors into frames from the real `words.json`. If narration is longer than the scene plan, scenes extend/hold; never cut
  narration. Overlap rules: one narration track, no SFX inside the first 150 ms of a stressed word unless `purpose: sync`.
- **Caching:** scene cache key = sha256(scene JSON + referenced asset file hashes + renderer package-lock hash + render
  profile). TTS cache = repo `kokoro_worker` key (text + delivery). Re-rendering one scene never rebuilds the others.
- **Resources:** bounded Remotion `concurrency` (start 3, benchmark 2–5), one heavy step at a time (repo rule: refuse while
  another step of the job is RUNNING), disk check before render (estimate = frames × measured MB/frame × 1.5), temp files in
  `<job>/tmp/` deleted on success, kept on failure for resume, peak RSS logged per step.
- **Job record:** `jobs/<slug>/job-NNN_<date>/state.json` (RUNNING/COMPLETED/FAILED/NEEDS_REVIEW, stage list, cost ledger,
  errors), atomic writes via repo `artifacts.replace_file` pattern. Failure classes: retryable (network, transient render
  crash: 2 retries with backoff), permanent (schema/config: stop), human-review (editorial gates: stop with NEEDS_REVIEW).
- **No public publish path in code.** S17 records a video ID the creator supplies after a manual upload (as repo `record`
  does). Optional later: repo `publish.py` pattern (Private only, `--yes`, plus a stored creator-approval record) — never public.
- **Secrets:** env vars or gitignored files only (`tools/gemini/api_key.txt` pattern), never logged; hook blocks committing them.
